# pages_messaging

Exact permission name: `pages_messaging`. Family: Facebook Login, Page access. It lets the app send and receive messages for a Facebook Page the user manages. It does not cover Instagram messaging. Instagram uses a different permission name.

Full walkthrough: [pages_messaging App Review](https://singhamandeep.com/pages-messaging-app-review/).

## Before you add it

- [ ] The app is in a Meta Business that can complete Business Verification if Meta asks.
- [ ] You are requesting `pages_messaging`, not a similarly named Page permission you do not use.
- [ ] The use case text matches one allowed usage on the [Permissions Reference](https://developers.facebook.com/documentation/development/permissions).
- [ ] A Facebook Page you control is connected, and the test user can open that Page inbox.
- [ ] The webhook (if you use one) answers Meta’s verification challenge and is reachable on HTTPS.

## What the screencast has to show

- [ ] Login with the test account Meta was given.
- [ ] The Page conversation opening from a real person message, not a mocked screenshot.
- [ ] The app reading that message and sending a reply in the thread.
- [ ] The reply landing in the Page inbox or the user’s Messenger thread.
- [ ] No extra permissions clicked during the recording that are not in this submission.

## Reviewer notes that match policy

Messenger policy requires a real opt-in, a working opt-out, and respect for the standard messaging window (24 hours after the person messages the Page, longer only in the cases the docs name). Message tags are not a way to send promotions. See the [Messenger Platform policy](https://developers.facebook.com/documentation/business-messaging/messenger-platform/policy).

A recording of the dashboard settings page, with no message sent, is the usual “inadequate demonstration” rejection.

## Policy citations (checked 3 October 2026)

These are the live documents. Do not cite an older section number as if it were still the heading.

- [Meta Developer Policies](https://developers.facebook.com/devpolicy/), last updated 3 February 2026. **Section 1, item 6** says: follow the instructions in the Developer Docs, including allowed usage for Platform. That is the current “1.6” line. A submission whose screencast does not match the allowed usage for the permission you asked for is rejected.
- Older enforcement mail sometimes said **“Developer Policy 1.9: use of a permission is not visible in the app.”** The 3 February 2026 policy text does not keep that section number. The test is unchanged: [App Review](https://developers.facebook.com/docs/app-review) must be able to open the app and see that permission used for its allowed purpose. If the reviewer cannot reach that screen, the whole submission can fail.
- [Platform Terms](https://developers.facebook.com/terms): Meta can require App Review, and approval does not replace ongoing compliance.
- [Permissions Reference](https://developers.facebook.com/documentation/development/permissions): use the exact permission name and its allowed usage. Facebook Login permissions and Instagram Login permissions are different families.
- [Messenger Platform policy](https://developers.facebook.com/documentation/business-messaging/messenger-platform/policy): opt-in, the 24-hour standard messaging window, and message tags.
